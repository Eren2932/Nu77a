## 1. Кто и зачем

Автор — студент из России, бюджет близок к нулю. Nuva — мессенджер с упором на
приватность и на отсутствие единого владельца. Идея родилась в феврале 2025,
первая реализация (рабочая, но с плохой оптимизацией, на Firebase, под именем
**EonChat**) была заброшена. В октябре 2025 переименована в **Nuva**. Текущий
проект — **полное переписывание с нуля**, начатое 25 августа 2026.

Слоган в интерфейсе: *«Your words. Your rules.»*

**Формат работы:** ассистент пишет код и отдаёт его архивом. Автор заливает в
GitHub, сборка идёт через **GitHub Actions** — прямого доступа к ПК автора у
ассистента нет. **CI является настоящим компилятором проекта**: в песочнице
ассистента нет ни Go, ни Android SDK, скомпилировать код до пуша невозможно.
Это принято как данность, а не как проблема.

**Обратная связь:** автор присылает **точный текст ошибки из лога**, не
пересказ. Этот приём уже дважды дал точный диагноз за минуту.

## 2. Продуктовые решения (приняты и закрыты, не пересматривать без причины)

| Решение | Причина |
|---|---|
| **Не Firebase** | Бесплатный тариф упирался в стену (голосовые максимум 40 сек), ноль контроля, все данные у Google — идеологическое противоречие с проектом о приватности, риск блокировки аккаунта из РФ |
| **Свой сервер на Go** | Один бинарник, ~40 МБ RAM в простое, десятки тысяч WS-соединений на ядро. На Node/Python тот же профиль требовал бы VPS в 4–8 раз дороже |
| **Адрес сервера вводит пользователь** | Нет единого владельца. Побочный и очень важный эффект: смена транспорта (туннель, LAN, VPS) не требует новой сборки APK |
| **Одно устройство = один аккаунт в 1.0** | Мультидевайс + E2EE ломает даже большие команды. Перенесено в 1.1 |
| **E2EE в 1.0 НЕТ** | В 1.1 берём готовый Signal Protocol (X3DH + Double Ratchet). Свою криптографию не пишем никогда |
| **AGPL-3.0** | Публичный изменённый инстанс обязан открыть исходники. Именно это делает фразу «поднимай свой сервер» настоящей |
| **Публикация: GitHub Releases + RuStore** | Google Play — $25 и риски, пока не нужен |

### Что запрещено писать в маркетинге до реализации
- Ничего со словами **«end-to-end»** до версии 1.1
- Никакого **«никто не сможет прочитать»**
- Никакой политической рамки — привлечение внимания, которое проект не переживёт

Причина простая: первый же человек, который откроет исходники и найдёт
расхождение с обещаниями, похоронит репутацию проекта о приватности.
Формулировки, которые можно использовать честно, лежат в `docs/MODEL.md` и
`docs/SECURITY.md`.

## 5. Что РАБОТАЕТ на 25 августа 2026 (проверено на реальном устройстве)

### Сервер
- `GET /healthz`, `GET /readyz`, `GET /v1/meta` (версия API, лимиты, число онлайн)
- `POST /v1/auth/register` — bcrypt cost 12, выдаёт `recovery_code` **один раз**
  (в базе только хеш, повторно выдать нельзя)
- `POST /v1/auth/login` — неверный логин и неверный пароль дают **одинаковый**
  `401 invalid_credentials`, чтобы нельзя было собрать список username
- `POST /v1/auth/refresh` — refresh 32 случайных байта, в базе **только SHA-256
  хеш**, токен **одноразовый**, ротируется при каждом обновлении
- `POST /v1/auth/logout`
- `GET /v1/me`
- `GET /v1/ws` — WebSocket: `hello`, heartbeat 30 сек, `echo`. Хаб с буфером на
  64 сообщения на клиента: один зависший телефон не может затормозить сервер
- Формат ошибки всегда один: `{"error":{"code":"...","message":"..."}}`
- Миграции: каждая в транзакции вместе с записью о себе — «наполовину
  применённая» невозможна
- Конфиг падает на старте со списком недостающих переменных

### Схема БД (0001_init.sql, уже применена)
`users`, `sessions` — используются.
`conversations`, `messages` и связанные — **таблицы созданы заранее**, чтобы
контракт клиента не поехал в спринте 2, но кодом пока не тронуты.

### Android
- Экран **Choose your server**: ввод адреса, `ServerUrl.normalize()` с 11
  юнит-тестами. Кандидат **не сохраняется**, пока сервер не ответит на
  `/v1/meta` — опечатка не может запереть приложение
- Экраны **Sign in / Create account** с валидацией
- Экран **Home**: username, user id, версия приложения, адрес сервера, версия
  API, индикаторы `Realtime online` / `N online`, кнопки `Send echo` и
  `Refresh`, живой лог realtime
- Токены в `EncryptedSharedPreferences`, ключ в Android Keystore, бэкап в
  Google отключён
- Адрес сервера — в обычных `SharedPreferences` (намеренно: адрес не секрет, и
  сломанный keystore на кривой прошивке не должен заставить приложение забыть,
  где его сервер)
- Ktor сам обновляет токен на 401 и повторяет запрос — экраны про это не знают
- Реконнект WS с джиттером (без него все телефоны переподключатся в одну
  секунду и уронят сервер повторно)
- Навигация от факта наличия сессии, а не от стека — застрять «наполовину
  вышел» невозможно
- Смена сервера **всегда** стирает сессию
- Release-сборка **отказывается** от `http://`; debug принимает

### Инфраструктура и CI
- `docker compose up -d --build` поднимает Postgres + сервер
- `--profile tls` добавляет Caddy с автоматическим Let's Encrypt (для VPS)
- GitHub Actions: debug APK на каждый push + подписанный release APK по тегу
- Юнит-тесты гоняются в CI на каждой сборке
- Release-сборка **валится с текстовой инструкцией**, если нет keystore.
  Молчаливого фолбэка на debug-ключ не существует

### Подтверждённый рабочий контур
Регистрация → токены → защищённый запрос → живой WebSocket → echo обратно.
Скриншот получен: пользователь `devzis`, `Realtime online`, `1 online`,
`hello` с `api_version: v1` и `heartbeat_secs: 30`.

Приложение **ещё не мессенджер**. Это доказанный вертикальный срез
инфраструктуры. Отсутствует:

- ❌ **Чаты и сообщения** — ни списка диалогов, ни отправки, ни доставки
- ❌ Локальный кэш сообщений (SQLite/Drift) и оффлайн-очередь

- ❌ Медиа: фото, файлы, **голосовые**
- ❌ Группы, роли
- ❌ Пуш-уведомления, фоновый сервис
- ❌ Профиль: редактирование, аватар, ввод recovery-фразы для восстановления
- ❌ **E2EE** (запланировано на 1.1, не на 1.0)
- ❌ Свой визуальный язык — сейчас стандартный Material 3. Автор высказал

- ❌ Веб-версия (`docs/WEB.md`, сервер к ней готов: токен принимается и в
  заголовке, и в query, потому что браузер не может задать заголовок при

- ❌ iOS, Windows-клиент
- ❌ `LICENSE`
- ❌ VPS, домен, продакшн-деплой
- ❌ Release-сборка по тегу **ни разу не проверялась** — путь через R8 и подпись

## 7. Журнал провалов и уроки (главная ценность этого файла)

Все шишки этого дня. Каждая уже закрыта, но правило из каждой остаётся.

### 7.1 «Приложение конфликтует с другим файлом» (боль из прошлого проекта)
Диагноз: каждая сборка подписывалась разным ключом, Android видел «другое
приложение с тем же ID» и требовал удалить старое вместе с данными.
**Лечение:** один release keystore, в GitHub Secrets как base64, фиксированный
`applicationId club.nuva.app`. Новые версии ставятся **поверх**.
**Правило:** keystore забэкапить в три места. Потеряешь один раз — потеряешь
всех пользователей навсегда.

### 7.2 Три ошибки компиляции Kotlin (прогон 1)
- `NuvaApi.kt` — `request.url` это `URLBuilder`, а не `Url`; свойства
  `encodedPath` у билдера в Ktor 2.x нет → `request.url.buildString()`
- `NuvaApi.kt` — `override fun log(message: String) = Log.d(...)`: `Log.d`
  возвращает `Int`, expression-body сломал возвращаемый тип → блок в скобках
- `RealtimeClient.kt` — коллизия имён с сессией Ktor

### 7.3 Коллизии имён с WebSocket-сессией (прогоны 1–2) — самый опасный баг
У `DefaultClientWebSocketSession` есть **три** члена, совпавших с нашими:
`incoming`, `outgoing`, `send`. Наше свойство побеждало в разрешении имён.
`send(frame)` при этом **скомпилировался бы** и уехал в релиз как «сообщения
не доходят, а логи чистые» — такой баг ищется неделю.
**Лечение структурное:** `incoming`→`events`, `send`→`enqueue`, а работа с
сокетом вынесена в `runSession(session: DefaultClientWebSocketSession)` —
внутри этой функции неявного receiver'а сессии **нет вообще**, любое
обращение обязано быть написано `session.send`, `session.incoming`.
**Правило:** не переименовывать по одному, закрывать класс ошибок целиком.

### 7.4 R8 положил бы релиз уже после зелёного debug
Ktor ссылается на JVM-only классы (`java.lang.management`, `javax.naming`),
которых на Android нет. Debug это не трогает, `assembleRelease` падает на
«Missing class». Добавлены `-dontwarn` в `proguard-rules.pro`.
**Правило:** debug зелёный ≠ release зелёный. Проверять оба пути.

### 7.5 Cloudflare Tunnel не работает из России — вычеркнут насовсем
Пречек cloudflared: DNS `argotunnel.com` **PASS**, UDP/7844 **FAIL**,
TCP/7844 **FAIL**, `api.cloudflare.com:443` **PASS**. Оба транспорта
заблокированы на стороне сети. Профили `tunnel` и `tunnel-named` **удалены**
из `docker-compose.yml` с пояснением в шапке файла.
**Правило:** не предлагать Cloudflare Tunnel для РФ. Никогда.

### 7.6 Главный провал дня: в `docker-compose.yml` не было `ports:`
У сервиса `server` отсутствовала публикация порта. Сервер был доступен
**только внутри docker-сети**. Это одной строкой ломало сразу всё:

| Симптом | Причина |
|---|---|
| `http://192.168.0.6:8080` → `No connection` | на ПК на 8080 никто не слушает |
| localhost.run → `No connection` | туннель пробрасывал в пустой `127.0.0.1:8080` |
| Pinggy → `GET Reset /v1/meta` | TCP **RST** = порт закрыт. Сигнал доходил, дверь закрыта |
| Cloudflare **доходил** до сервера | он жил в той же docker-сети (`url:http://server:8080`) |

Несколько часов ушло на диагностику провайдера, файрвола и мобильного
оператора, тогда как всё было исправно.
**Правило, вписанное в `FIXES`:** при любой проблеме доступности **первым
делом** `docker compose ps` и проверка `0.0.0.0:8080->8080/tcp`, до любых
разговоров о сети.
**Лечение:** `docker-compose.override.yml` с `ports: - "0.0.0.0:8080:8080"`,
плюс в основном compose — `"${NUVA_BIND_ADDR:-0.0.0.0}:${NUVA_HOST_PORT:-8080}:8080"`.

### 7.7 `adb` не в PATH
`adb reverse` не сработал: `is not recognized as an internal or external
command`. Написан `scripts/adb-setup.ps1` — качает официальные
platform-tools и зовёт `adb.exe` **полным путём**, PATH не трогает.

## 8. Как сейчас всё запускается (рабочая конфигурация)

```powershell
# 1. секреты
cp .env.example .env
./scripts/gen-secrets.sh

# 2. поднять (override уже публикует порт)
docker compose up -d --build
docker compose ps          # ОБЯЗАТЕЛЬНО: 0.0.0.0:8080->8080/tcp
curl http://localhost:8080/v1/meta

# 3. подготовить Windows под Wi-Fi (от администратора)
powershell -ExecutionPolicy Bypass -File .\scripts\lan-setup.ps1

# 4. если Wi-Fi капризничает — по кабелю, гарантированный путь
powershell -ExecutionPolicy Bypass -File .\scripts\adb-setup.ps1
# затем в приложении: http://localhost:8080
```

**Адрес, на котором всё заработало у автора:** `http://10.0.2.2:8080`
(его локальная сеть; `http://` разрешён только в debug-сборке).

**Показать другим людям (Cloudflare не использовать):**
```powershell
ssh -R 80:localhost:8080 nokey@localhost.run    # https://xxx.lhr.life
ssh -p 443 -R0:localhost:8080 a.pinggy.io       # прямо по 443, пролезает везде
ssh -R 80:localhost:8080 serveo.net             # третий запас
```

## 9. Деньги и путь на настоящий сервер

Сейчас расходы — **0 ₽**: сервер на ПК автора, доступ по LAN/USB/SSH-туннелю.

Переезд на VPS запланирован на **октябрь**:

| Что | Где | Цена |
|---|---|---|
| VPS 1 vCPU / 1 GB / 15–25 GB | Aeza · VDSina · Timeweb Cloud (карта Мир) | ~130–200 ₽/мес |
| Домен `.ru` | reg.ru | ~200 ₽/год |
| TLS | Let's Encrypt через Caddy | 0 ₽ |
| Сборки, релизы, хостинг кода | GitHub Actions + Releases | 0 ₽ |

Апгрейд до 2 ГБ (~400 ₽) понадобится к нескольким сотням живых пользователей,
не раньше. Голосовые: Opus 24 kbps ≈ 180 КБ/минута, на 40 ГБ влезает
~200 000 минут. Лимита на длину нет (`voice_max_seconds: 0` в `/v1/meta`).

**Переезд = одна команда**, это заложено заранее:
```bash
# в .env: NUVA_BIND_ADDR=127.0.0.1  (открытый HTTP видит только Caddy)
docker compose --profile tls up -d --build
```

## 12. Правила проекта (соблюдать без напоминаний)

1. **Монорепа.** Один PR = согласованные изменения клиента и сервера.
2. **Версионирование API `/v1`.** Юзер со старым APK не отваливается при деплое.
3. **Миграции с первого дня.** Ни одного `ALTER TABLE` руками. Применённую
   миграцию не редактировать — добавлять новый номерной файл.
4. **Ноль секретов в коде.** Всё через env + GitHub Secrets. `config.go` —
   единственное место чтения окружения, сервер падает на старте со списком
   недостающих переменных.
5. **Версии зависимостей Android — только в `libs.versions.toml`.**
6. **Не писать свою криптографию.** Только готовый Signal Protocol в 1.1.
7. **Не обещать в маркетинге то, чего нет в коде.**
8. **Отдавать код целиком, без «тут допиши сам».**
9. **Говорить честно, чего не проверял.** Скомпилировать локально нельзя — CI
   и есть компилятор, это признаётся прямо, а не заметается.
10. **Каждый разобранный провал — запись в `FIXES`.** Через три месяца это
    экономит дни.
11. **Проблема доступности → сначала `docker compose ps`.** (см. 7.6)
