## 1. Суть проекта

Глобальный мессенджер, ставящий во главу свободу общения, конфиденциальность и защиту пользователя.

### Принципы (не нарушать)
1. **E2EE по умолчанию для всего**: сообщения, медиа, истории, звонки, бэкапы. Незашифрованных «облачных» чатов нет.
2. **Сервер ничего не знает**: хранит только шифротекст и минимум метаданных для доставки.
3. **Минимизация данных**: нет логов IP, нет аналитики содержимого, нет номера телефона.
4. **Никакой самописной криптографии на уровне примитивов.** Только libsodium; конструкции — по опубликованным спецификациям (Noise, Signal, MLS).
5. **Без номера телефона и SMS.** Вход: ключ устройства + инвайт + юзернейм.
6. **Проектируем под масштаб, стартуем дёшево.** Модульный монолит, без преждевременных микросервисов.
7. **Централизованная архитектура** (без федерации).

### Аудитория
- Старт: владелец + 5–10 тестеров / друзей. Первая волна — РФ / СНГ, далее глобально.
- Следствие: доступность из РФ — требование. Cloudflare не используем (в РФ замедляется); прокси в клиенте — в план.

### Монетизация
Подписка на премиум-кастомизацию и расширенные лимиты. Без рекламы, без продажи данных.

## 4. Функционал

### Фаза 1 — PoC (только технический прототип)
- Регистрация: ключи на устройстве + инвайт + юзернейм
- Авторизация устройства challenge-response (Ed25519)
- Поиск собеседника по юзернейму, получение его ключей
- 1:1 E2EE-текст, офлайн-доставка (store-and-forward), ack → удаление с сервера
- Safety number (сверка ключей), предупреждение при смене ключа
- Android + Desktop, приложение в foreground (без push)

### Альфа (тестеры, 5–10 человек)
- Фото / файлы / голосовые (E2EE, через S3 + presigned URL)
- Квитанции «доставлено / прочитано» (E2EE, отключаемые)
- Профиль: имя и аватар — шифруются для контактов
- Фоновая доставка на Android (FCM-«будильник» без содержимого или foreground service / UnifiedPush)
- Блокировка, удаление аккаунта
- Ответы, редактирование, удаление сообщений

### Бета / v1
- **Гейт ADR-013:** ратчет-протокол
- Группы (MLS, ADR-005), мультидевайс
- Кружки (видео; свой стиль — фишка бренда), истории (24 ч)
- Исчезающие сообщения, зашифрованный бэкап
- Прокси в клиенте (блокировки)
- iOS

### v2+
- Звонки 1:1 (WebRTC), групповые (SFU + SFrame), каналы / сообщества, приватный поиск контактов, Key Transparency, премиум-подписка

### Не делаем
Облачные незашифрованные чаты, рекламу, федерацию, вход по номеру.

## 5. Архитектура

```
 [Android]        [Desktop: Win/Linux/macOS]        ([iOS] — этап 2)
      \                    |                         /
       Compose Multiplatform UI (androidMain / desktopMain / commonMain)
                           |
   core (commonMain, чистый Kotlin):
     crypto   — libsodium (KMP-биндинги), конверт v1
     protocol — kotlinx.serialization, модели фреймов
     net      — Ktor WebSocket-клиент, реконнект, ping
     db       — SQLDelight + SQLCipher
     sync     — очередь исходящих, ack, ретраи
                           |
             WSS (TLS 1.3), JSON-фреймы, base64url
                           |
             Caddy (TLS, reverse proxy, без логов IP)
                           |
   FastAPI (uvicorn, 1 воркер в PoC) — модульный монолит:
     ws/gateway · auth · accounts · keys · messaging · invites · (media — альфа)
        |                 |                       |
   PostgreSQL       Redis/Valkey             MinIO / S3
   (аккаунты,       (с >1 воркера:           (альфа: зашифрованные
    устройства,      pub/sub, rate limit,      блобы медиа)
    очередь)         presence)
```

### Ключевые решения
- **1 воркер uvicorn на PoC/альфе**: реестр соединений `device_id → websocket` в памяти. При >1 воркере / узле — маршрутизация через Redis pub/sub (у каждого воркера свой процесс и своя память — та же грабля, что в ZiziPlayer).
- **Store-and-forward**: сервер хранит конверт до ack от устройства получателя, потом удаляет. TTL недоставленного — 30 дней.
- **Fan-out на клиенте**: отправитель шифрует отдельно для каждого устройства получателя (и для своих других устройств).
- **Медиа (альфа)**: клиент шифрует файл → presigned PUT → загрузка в S3 мимо API → ссылка, ключ и хеш уходят внутри E2EE-сообщения.
- **Push (альфа)**: только «разбуди», без содержимого и отправителя.

### Технические заметки по клиенту
- **Криптобиблиотека для `commonMain`**: `com.ionspin.kotlin:multiplatform-crypto-libsodium-bindings` — покрывает Android, JVM-десктоп и iOS. `lazysodium` — только JVM / Android, на iOS придётся менять. `cryptography-kotlin` (whyoleg) — проверить поддержку XChaCha20, иначе AES-256-GCM.
- **HKDF**: если в биндингах нет `crypto_kdf_hkdf_sha256` — реализовать по RFC 5869 поверх HMAC-SHA256 и проверить тест-векторами из RFC.
- **SQLCipher на десктопе**: обычный `sqlite-jdbc` не шифрует. Нужен JDBC-драйвер с поддержкой SQLCipher (напр. `sqlite-jdbc-crypt` от Willena — проверить актуальность). Android: `net.zetetic:sqlcipher-android`.
- **Хранение ключа БД**: Android Keystore; Desktop — системный keychain (Windows Credential Manager / macOS Keychain / Secret Service), напр. `java-keyring`.
- **ZiziPlayer** — референс по стилю кода и процессу (CI, handoff-документы), не по архитектуре. Его правило «никаких секретов в коде» переносим 1:1.

## 6. Криптография и защита

### 6.1 Ключи устройства
- `IK` — Ed25519 (идентичность устройства, подпись challenge).
- `XK` — X25519 (шифрование), подписан `IK` (`x25519_sig`).
- Приватные ключи не покидают устройство; хранятся в зашифрованной БД / keychain.

### 6.2 Конверт v1 (PoC / альфа) — детали в `NUVA_PHASE1_POC.md` §4
- Noise one-way `K`: эфемерный X25519 на каждое сообщение; `es` + `ss` → HKDF-SHA256 → ключ → XChaCha20-Poly1305 (AD = заголовок).
- **Даёт:** конфиденциальность, аутентификацию отправителя, уникальный ключ на сообщение, частичную FS при компрометации отправителя.
- **НЕ даёт:** forward secrecy при краже ключа получателя (вся его переписка вскрывается), post-compromise security. → ADR-013, гейт перед бетой.

### 6.3 Доверие к ключам
- TOFU: клиент закрепляет `IK` собеседника при первом контакте; при смене — заметное предупреждение.
- Safety number: SHA-256 от отсортированных `IK` обеих сторон → 60 цифр + QR.
- Позже: Key Transparency (защита от подмены ключей сервером).

### 6.4 Медиа (альфа+)
Случайный ключ на файл, XChaCha20-Poly1305 потоково (`secretstream`) для больших файлов. EXIF / гео вырезаются до шифрования. Превью тоже шифруются.

### 6.5 Метаданные
- Без логов IP (Caddy и uvicorn access-log выключены или без IP).
- `last_seen` на сервере — с точностью до дня.
- Паддинг plaintext до кратного 256 байтам.
- Sealed sender — после ADR-013 (в v1 сервер знает `sender_device_id`).

### 6.6 Инфраструктура
SSH только по ключам, firewall (443 + 22), fail2ban / crowdsec, секреты в `.env` (не в git), приватный репозиторий без IP и ключей. В публичном репо ZiziPlayer уже лежат IP сервера и устройство VPN-стека — для мессенджера так нельзя.

## 8. Инфраструктура и хостинг

### 8.1 План по этапам
| Этап | Где | Состав |
|---|---|---|
| PoC | Единый сервер Aeza, Стокгольм (ADR-003) | Caddy + FastAPI + PostgreSQL (Redis не обязателен) |
| Альфа | Он же (если хватит диска, см. §8.2) | + S3 (MinIO / Garage), + бэкапы `pg_dump` |
| Публичная бета | Hetzner Хельсинки (≈ €8–15 VPS → выделенный ≈ €40–50) | + Redis, мониторинг, 2-й узел |
| Рост | Hetzner / OVH, мульти-регион | Кластеры, отдельные TURN / SFU |

### 8.2 Единый сервер (Aeza, Стокгольм) — факты
> Источник правды — панель Aeza (скрин владельца, 2026-10-31) и `SERVER.md` в репо ZiziPlayer.
> **Timeweb — история.** Любые упоминания Timeweb / 890 МБ RAM / 15 ГБ в старых документах ZiziPlayer устарели.

| Параметр | Значение |
|---|---|
| Провайдер / локация | Aeza, Стокгольм (Швеция) |
| Тариф | `SWE-PROMO`, €1.99/мес, оплачен до **30.11.2026** — проверить цену продления после промо |
| CPU / RAM / диск | **1 ядро / 4 ГБ / 10 ГБ NVMe** |
| Канал | до 300 Мбит/с |
| ОС | Ubuntu 22.04 |
| IP | не хранить в публичных репозиториях; в `.env` / приватных заметках |
| Соседи | ZiziPlayer (FastAPI + yt-dlp + Deno, `:8080`; xray `127.0.0.1:1080`) |

**Оценка для мессенджера:**
- **RAM 4 ГБ — запаса много.** Zizi ~0.2–0.5 ГБ с пиками Deno; Nuva PoC ~0.3 ГБ (FastAPI, PostgreSQL с `shared_buffers=64MB`, Caddy); даже S3 на альфе влезет.
- **1 ядро — общее с yt-dlp / Deno.** Для 5–10 человек и текста незаметно; при одновременном резолве трека возможны задержки WS в сотни мс. Терпимо для альфы.
- **10 ГБ диска — главное узкое место.** ОС ~3 ГБ + Zizi (venv, Deno, склад аудио — квота до 3 ГБ) + Docker-образы ~1 ГБ → под Nuva остаётся ~2–3 ГБ. На текст хватит с избытком; на кружки и голосовые в альфе — нет. Варианты к альфе: уменьшить квоту склада Zizi, докупить диск у Aeza или вынести S3 на отдельное хранилище.

**Правила соседства:**
- Nuva живёт в `/opt/nuva`, docker compose project `nuva`, свой `.env`. Zizi не трогаем, и наоборот.
- Порты: Caddy Nuva — `80/443`; API и PostgreSQL — только во внутренней docker-сети, наружу не публикуются. `8080` и `1080` заняты Zizi.
- Лимиты памяти в compose (`mem_limit`: api 256m, postgres 384m, caddy 64m) — чтобы мессенджер не мог устроить OOM для Zizi.
- Disk guard: `docker system prune` в cron + алерт при заполнении диска > 85%.

**Безопасность сервера (сделать до PoC):** вход по SSH-ключам, `PasswordAuthentication no`, отдельный sudo-пользователь вместо root, ufw (22, 80, 443, 8080), fail2ban. Сейчас в панели вход root по паролю.

### 8.3 Хранилище медиа
- MinIO: в 2025 community-версия урезана (убрана веб-консоль; публикация готовых образов прекращена) — **проверить состояние на момент альфы**.
- Запасные, S3-совместимые, presigned URL работают: **Garage** (лёгкий, для одного узла — идеален), **SeaweedFS**. Схема клиента от выбора не меняется.

### 8.4 Провайдеры на будущее (цены примерные — сверять)
Hetzner (HEL1 / FSN1 / NBG1) — основной кандидат; Netcup — дёшево; OVHcloud — анти-DDoS; UpCloud — есть Стокгольм, дороже; Infomaniak / Exoscale (CH) — дорого, сильная юрисдикция. **На публичном этапе исключены:** серверы в РФ, Aeza (ADR-002).
Оплата: карты РФ не принимаются — нужна зарубежная карта / юрлицо.

## 9. Аутентификация
- **Без SMS и телефона** (ADR-006). Инвайт-код: одноразовый, хранится как SHA-256, срок 14 дней.
- Вход: подпись Ed25519 серверного nonce (протокол — в спецификации Фазы 1).
- Восстановление аккаунта: в PoC нет (потерял устройство → новый аккаунт). Альфа/бета: привязка нового устройства через QR со старого + фраза восстановления для бэкапа.
- **Архив исследования SMS** (на случай, если номер когда-то станет опцией): дешевле всего Telegram Gateway (~$0.01 / код, но это зависимость от конкурента) и flash call; Twilio Verify — дорого; обязательна защита от SMS pumping.

## 12. Название

`Nuva` — рабочее. Минус: ассоциация с NuvaRing (контрацептив) в англоязычном поиске. Владелец хочет другое.

### Критерии
4–6 букв; одинаково читается по-русски и по-английски; без плохих значений в крупных языках; свободны `.app` / `.chat` / `.im` и хэндлы; нет конфликта в классах ТЗ 9 / 38 / 42; не похоже на существующие мессенджеры.

### Шортлист (НЕ проверен на занятость)
| Имя | Смысл | Комментарий |
|---|---|---|
| **Kolo** | «коло» — круг (общеслав.) | Связь с фирменными кружками; читается везде |
| **Tiho** | «тихо» (рус., серб., хорв., слов.) | Приватность одним словом; славянский старт → глобал |
| **Vela** | «паруса» (лат.), созвездие | Свобода, движение; исп. «свеча» — нейтрально |
| **Arca** | «ларец, ковчег» (лат.) | Хранилище, защищённость |
| **Clave** | «ключ» (лат. / исп.) | Шифрование; по-русски «Клаве» — мягче |

Выбрать 3 → домены + поиск в Google Play / App Store + WIPO Brand DB (кл. 9/38/42) → тест «произнеси вслух» с 5 людьми (RU + EN) → значение в ~10 языках → решение до публикации в сторе (ADR-018).

## 14. Глоссарий
- **E2EE** — сквозное шифрование. **IK / XK** — ключи устройства Ed25519 / X25519.
- **Noise `K`** — односторонний паттерн Noise Protocol Framework: отправитель знает статический ключ получателя; токены `e, es, ss`.
- **Forward secrecy** — кража текущих ключей не раскрывает прошлое. **PCS** — самовосстановление после компрометации.
- **Store-and-forward** — сервер хранит конверт до доставки. **Fan-out** — копия конверта на каждое устройство.
- **TOFU** — доверие при первом контакте. **Safety number** — код сверки ключей.
- **Presigned URL** — временная ссылка на загрузку / скачивание в S3.
- **MLS** — RFC 9420, групповая E2EE. **Sealed sender** — сервер не знает отправителя.
