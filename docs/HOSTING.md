# Сервер: где держать и сколько это стоит

Задача: свой сервер, оплата картой из России, без VPN-костылей, дешевле пиццы
в месяц.

## Что нам реально нужно

Go-сервер в простое ест ~40 МБ RAM. Один WebSocket = ~10–20 КБ памяти.
Считаем честно:

| Активных пользователей | RAM сервера | Postgres | Итого VPS |
|---|---|---|---|
| 100 | ~60 МБ | ~200 МБ | 1 ГБ хватает |
| 1 000 | ~120 МБ | ~400 МБ | 2 ГБ комфортно |
| 5 000 | ~350 МБ | ~800 МБ | 2–4 ГБ |
| 20 000 | нужен второй инстанс + Redis | 4 ГБ | 8 ГБ, ~2500 ₽/мес |

Диск: голосовое сообщение в Opus 24 kbps = **180 КБ/минута**.
40 ГБ диска ≈ **200 000 минут** голосовых. Это не Firebase с лимитом 40 секунд.

## Провайдеры (карта Мир работает)

| Провайдер | Конфигурация | Цена | Комментарий |
|---|---|---|---|
| **Timeweb Cloud** | 2 vCPU / 2 ГБ / 40 ГБ NVMe | ~400 ₽/мес | панель простая, S3 у них же, есть бэкапы за копейки. **Мой выбор на старт** |
| Aeza | 2 vCPU / 2 ГБ / 30 ГБ | ~350 ₽/мес | дёшево, принимают карты и крипту |
| VDSina | 1 vCPU / 1 ГБ / 25 ГБ | ~250 ₽/мес | самый дешёвый вход, хватит до ~500 юзеров |
| Selectel | 2 vCPU / 2 ГБ | ~500 ₽/мес | серьёзнее и стабильнее, дороже |
| **Oracle Cloud Free** | 4 ARM ядра / 24 ГБ / 200 ГБ | **0 ₽** | бесплатно навсегда, но карта для верификации и регистрация из РФ проблемная. Если получится — это подарок |

Домен: `reg.ru`, `.ru` ≈ 200 ₽/год. TLS — Let's Encrypt через Caddy, бесплатно
и автоматически.

**Итог на старт: ~600 ₽/мес** за всё (VPS + домен). Этого хватит минимум до
первой тысячи пользователей.

## Хранилище медиа

Три этапа, переключаемся когда упираемся:

1. **Сейчас:** диск VPS, том `media_data`. 0 ₽. Хватит на первые месяцы.
2. **~30 ГБ медиа:** S3 у того же провайдера (Timeweb S3 ≈ 2 ₽/ГБ/мес).
   Клиент грузит файлы напрямую по presigned URL — сервер не тратит трафик.
3. **Много трафика:** Cloudflare R2 (0 ₽ за исходящий трафик), если получится
   оплатить.

## Развёртывание с нуля (~15 минут)

```bash
# 1. На свежем Ubuntu 24.04
apt update && apt install -y docker.io docker-compose-v2 git ufw
systemctl enable --now docker

# 2. Файрвол: наружу только SSH и HTTPS
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable

# 3. Код
mkdir -p /opt && cd /opt
git clone https://github.com/ТВОЙ_АККАУНТ/nuva.git
cd nuva

# 4. Секреты и домен
cp .env.example .env
./scripts/gen-secrets.sh
nano .env          # NUVA_DOMAIN, NUVA_ACME_EMAIL, NUVA_ALLOWED_ORIGINS

# 5. Поехали
docker compose up -d --build
docker compose logs -f server
```

DNS: A-запись `api.nuva.club` → IP сервера. Caddy сам получит сертификат при
первом обращении.

Проверка:

```bash
curl https://api.nuva.club/healthz     # {"status":"ok"}
curl https://api.nuva.club/readyz      # {"status":"ready"}
./scripts/smoke-test.sh https://api.nuva.club
```

## Бэкапы (сделай в первый же день)

Мессенджер без бэкапа базы — это мессенджер, который однажды исчезнет.

```bash
# /etc/cron.daily/nuva-backup
#!/bin/sh
set -e
cd /opt/nuva
mkdir -p /var/backups/nuva
STAMP=$(date +%F)
docker compose exec -T db pg_dump -U nuva nuva | gzip > /var/backups/nuva/db-$STAMP.sql.gz
# держим 14 дней
find /var/backups/nuva -name 'db-*.sql.gz' -mtime +14 -delete
```

```bash
chmod +x /etc/cron.daily/nuva-backup
```

Раз в неделю скачивай дамп себе на диск. Бэкап, который лежит только на том же
сервере, — это не бэкап.

## Что делать, когда одного сервера не хватит

Порядок ровно такой, не наоборот:

1. Postgres на отдельный VPS (обычно он упирается первым).
2. Медиа в S3.
3. Второй инстанс сервера + Redis pub/sub за интерфейсом `ws.Hub`
   (код уже написан так, что менять придётся один файл).
4. Балансировщик перед инстансами со sticky-сессиями по WebSocket.

## Про блокировки и устойчивость

* Сервер в РФ — быстрее для наших пользователей и никаких проблем с оплатой.
* Домен лучше взять и `.ru`, и что-то нейтральное — на случай проблем с одним
  из регистраторов.
* Клиент читает адрес API из `BuildConfig`, поэтому смена домена = новая
  сборка. В 1.1 добавим список резервных адресов, чтобы приложение само
  переключалось.
