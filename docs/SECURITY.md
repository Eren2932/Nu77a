# Безопасность: что защищено сейчас

Этот файл существует, чтобы мы **никогда** не обещали пользователям защиту,
которой в коде нет. Первый же энтузиаст, который откроет исходники и найдёт
расхождение с обещаниями, похоронит репутацию проекта о приватности.

## Что реально работает в 1.0

| Что | Как |
|---|---|
| Трафик | TLS 1.2+ через Caddy, HSTS, сертификаты Let's Encrypt автоматически |
| Пароли | bcrypt, cost 12. Открытый пароль не хранится и не логируется |
| Сессии | refresh-токен в БД только как SHA-256 хеш, одноразовый, ротируется |
| Access-токен | JWT HS256, 15 минут, привязан к id сессии, проверяется issuer и audience |
| Токены на телефоне | EncryptedSharedPreferences, ключ в Android Keystore |
| Бэкап Android | отключён: токены и кеш не уезжают в Google-аккаунт |
| Перебор username | вход и «нет такого пользователя» дают один и тот же 401 |
| Восстановление | recovery-код, у сервера только bcrypt-хеш |
| SQL-инъекции | только параметризованные запросы pgx, конкатенации значений нет |
| Лимит тела запроса | 1 МБ на JSON, `DisallowUnknownFields` |
| Заголовки | nosniff, DENY на фреймы, no-referrer |
| Логи | ни одного токена, пароля или тела запроса в логах |
| Внутренние ошибки | клиенту уходит `internal_error`, детали только в лог сервера |
| Контейнер | процесс от непривилегированного пользователя uid 10001 |

## Чего пока НЕТ — говорим прямо

| Чего нет | Что это значит | Когда будет |
|---|---|---|
| E2EE | сообщения читаемы на сервере; кто владеет сервером, видит переписку | 1.1 |
| Шифрование БД на диске | дамп базы читается как есть | 1.1 |
| Rate limiting | пароль можно перебирать быстро | спринт 1 |
| 2FA | второго фактора нет | 1.2 |
| Верификация ключей | сверить отпечаток с собеседником нельзя | вместе с E2EE |
| Аудит третьей стороной | код никто не проверял | после 1.0 |

**Формулировка для лендинга и сторов, которую можно писать без вранья:**

> Nuva — мессенджер на собственном сервере с открытым исходным кодом. Трафик
> защищён TLS, пароли хранятся хешированными, токены — в защищённом хранилище
> Android. Сквозное шифрование личных переписок появится в версии 1.1.

Так писать **нельзя**: «полностью защищённый», «никто не может прочитать»,
«военное шифрование».

## План E2EE (версия 1.1)

1. Взять готовую библиотеку Signal Protocol. **Свою криптографию не писать
   никогда** — это гарантированная дыра.
2. X3DH для установки сессии, Double Ratchet для сообщений.
3. Identity key генерируется на устройстве, приватная часть не покидает его.
4. На сервер загружаются только публичные prekey-бандлы.
5. Личные чаты — E2EE. Группы — позже, там нужен sender key.
6. Восстановление: без резервной копии ключа история теряется. Пользователь
   должен понимать это до включения, а не после.
7. Мультидевайс — только после того, как один девайс работает идеально.
