# Веб-версия Nuva (после Android)

Решение, зафиксированное в спринте 0: веб — это **отдельный клиент к тому же
`/v1` API**, а не сборка мобильного кода под браузер.

## Почему отдельный клиент, а не «одна кодовая база»

* Мобильный код на Kotlin/Compose в браузер не собирается вообще (Compose Web
  для мессенджера пока не вариант).
* Если бы мы взяли Flutter ради «одного кода», веб получился бы плохим:
  бандл в несколько мегабайт, кривой ввод текста в поле, ломающееся выделение,
  отсутствие индексации. Для мессенджера ввод текста — главный элемент UI.
* Сервер уже отдаёт чистый JSON и WebSocket. Веб-клиент — это ~2 недели работы,
  а не месяцы: вся логика (сессии, ротация токенов, протокол) уже описана и
  проверена smoke-тестами.

## Стек, когда дойдём

| Слой | Выбор | Почему |
|---|---|---|
| Каркас | React 18 + TypeScript + Vite | быстрая сборка, всё знакомо |
| Состояние | TanStack Query + Zustand | кеш запросов из коробки |
| Стили | Tailwind CSS | без отдельной дизайн-системы |
| Роутинг | React Router | стандарт |
| Realtime | нативный `WebSocket` | тот же envelope-протокол |
| Хранение | `localStorage` для refresh, access только в памяти | XSS не должен утащить долгоживущий токен |
| Оболочка | PWA (manifest + service worker) | ставится на рабочий стол, работает офлайн-чтение |
| Хостинг | статика через тот же Caddy | 0 ₽, тот же домен, ноль CORS-проблем |

## Что придётся учесть отдельно

1. **WebSocket без заголовков.** Браузер не даёт задать `Authorization` при
   апгрейде. Сервер уже это умеет: `/v1/ws?access_token=...` — код в
   `middleware.go` (`bearerToken`) читает токен из query.
2. **CORS.** `NUVA_ALLOWED_ORIGINS` в `.env` уже управляет и CORS, и проверкой
   Origin для WebSocket в production.
3. **Хранение токенов.** Refresh в `localStorage`, access — только в памяти
   JS. При перезагрузке страницы делаем refresh. Компромисс осознанный.
4. **E2EE в браузере сложнее.** Ключи в IndexedDB защищены слабее, чем в
   Android Keystore. Когда дойдём до 1.1, веб честно помечаем как менее
   защищённый клиент.

## Когда

Не раньше, чем Android 1.0 выйдет и стабилизируется. Веб, начатый до релиза, —
это гарантированный срыв 10 декабря, потому что делить внимание между двумя
клиентами на одного человека невозможно.

Ориентир: **январь–февраль 2027**, версия 1.1.

## Что уже сделано для будущего веба

* Сервер отдаёт JSON, не HTML, и ничего не знает о клиентах.
* Токен принимается и в заголовке, и в query.
* CORS и проверка Origin вынесены в конфиг.
* Формат ошибок и envelope-протокол описаны в `API.md` — их не нужно
  реверс-инжинирить.
